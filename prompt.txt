==================================================
1. CONTEXTO DO PROJETO
==================================================

O projeto consiste em desenvolver um MVP de Engenharia de Dados capaz de transformar dados públicos relacionados ao Fundo Especial de Financiamento de Campanha (FEFC), disponibilizados pelo Tribunal Superior Eleitoral (TSE), em informações organizadas, confiáveis e visualmente acessíveis.

Fluxo conceitual:

TSE
 ↓
Airflow
 ↓
S3 - Bronze
 ↓
Transformação / Qualidade
 ↓
S3 - Silver
 ↓
Data Warehouse / Gold
 ↓
Dashboard

O Apache Airflow será responsável pela orquestração do pipeline.

O Amazon S3 será utilizado como Data Lake.

A arquitetura deverá seguir o conceito de Arquitetura Medalhão:

- Bronze: dados brutos, preservando a origem;
- Silver: dados tratados, padronizados e validados;
- Gold: dados consolidados e preparados para consumo analítico.

Para o MVP, a camada Gold poderá ser representada pelo Data Warehouse, utilizando PostgreSQL inicialmente, de forma que não seja necessário criar uma terceira camada física no S3 se isso não for necessário.

4. AIRFLOW
==================================================

Criar uma DAG inicial chamada:

fundo_eleitoral_pipeline

A DAG deverá representar conceitualmente o pipeline:

1. ingestão
2. armazenamento Bronze
3. transformação Silver
4. validação
5. carga Gold / Data Warehouse

Neste momento, as tasks podem possuir apenas implementação mínima/mock ou funções placeholder.

Não implemente ainda o processamento real.

Utilize TaskFlow API ou uma abordagem moderna e limpa do Airflow.

A DAG deve possuir:

- schedule configurável;
- start_date;
- catchup=False;
- retries configuráveis;
- organização lógica das tasks;
- logs;
- tratamento básico de erros.

Evite colocar toda a lógica de negócio diretamente dentro da DAG.

A DAG deve apenas orquestrar funções existentes em src/.

==================================================
5. ARQUITETURA MEDALHÃO
==================================================

Estruture o projeto considerando:

BRONZE
------
Responsável pelos dados brutos.

Características:
- preservar dados originais;
- não modificar conteúdo da fonte;
- armazenamento no S3;
- organização por eleição/ano.

Exemplo conceitual:

s3://<bucket>/bronze/fundo_eleitoral/ano_eleicao=2024/

SILVER
------
Responsável pelos dados tratados.

Características:
- limpeza;
- padronização;
- conversão de tipos;
- tratamento de valores nulos;
- remoção de duplicidades;
- validações básicas.

Exemplo:

s3://<bucket>/silver/fundo_eleitoral/ano_eleicao=2024/

GOLD
----
Responsável pelos dados consolidados para consumo analítico.

No MVP, utilizar PostgreSQL como Data Warehouse local.

A estrutura deve ficar preparada para posteriormente receber:

- tabelas fato;
- dimensões;
- agregações;
- indicadores.

Não criar ainda o modelo final porque ele será definido após a análise dos dados reais do TSE.
